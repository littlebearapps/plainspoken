# Getting help

plainspoken is made by Little Bear Apps. Start with the guides, then the doctor, then Discussions or an issue.

## Read the guides

- [The guides index](guides/README.md) lists every guide, from installing to the kaizen loop.
- [The FAQ](guides/faq.md) answers the common questions.
- [Troubleshooting](guides/troubleshooting.md) covers what to do when a skill, hook or check doesn't behave.

## Run the doctor

`/plainspoken:doctor` checks your install and prints what it found: Python, the plugin files, the reports folder,
your config files and, where the host has them, the plugin's agents. It changes nothing, and its output is the
first thing to paste into a bug report.

## Ask in Discussions

[GitHub Discussions](https://github.com/littlebearapps/plainspoken/discussions) is the place for questions and
ideas that aren't a bug yet. Ask how to set something up in
[Q&A](https://github.com/littlebearapps/plainspoken/discussions/categories/q-a), talk an idea through in
[Ideas](https://github.com/littlebearapps/plainspoken/discussions/categories/ideas), and follow
[Announcements](https://github.com/littlebearapps/plainspoken/discussions/categories/announcements) for what each
release changes.

## Open an issue

[Open an issue](https://github.com/littlebearapps/plainspoken/issues/new/choose) and pick the form that fits:

- **Bug report**, when something breaks or doesn't do what the docs say.
- **Feature request**, for a new feature or a change to how something works.
- **False positive**, **Missed tell** or **Pattern proposal**, when the checks flag writing that's fine, miss a tell
  or could catch a new one. These feed the [kaizen loop](guides/kaizen.md).

Don't paste private text into an issue. Anonymise it, or write a made-up example that shows the same thing.

## Security problems

Never report a vulnerability in a public issue. [SECURITY.md](SECURITY.md) explains how to report it privately.

## Anything else
