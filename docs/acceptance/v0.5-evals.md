# v0.5 trigger evals

Date: 2026-10-19 (Melbourne). Claude Code CLI 2.1.303, Linux, `claude plugin eval` against the local checkout on
`feature/pre-cutover`. The plugin still reports version 0.4.0 (the manifest isn't bumped until
release). Paid run, approved by the owner, capped at US$5.

Result: **30 of 30 cases passed, each at score 1.00, for US$3.58** (US$3.48 for the full run plus US$0.10 for the
smoke run). No skill description needed changing.

## Command

```bash
claude plugin eval . --tag trigger --allow-tools "Bash(python3 *)" --ablation none --runs 1 -j 4 \
  --no-publish --max-cost-usd 5 --threshold 0.8 --trust-plugin
```

The full run used `--max-cost-usd 4.8`, which was what was left after the smoke run. The flags are otherwise the
same as in `p3-evals.md`: `--ablation none` so the `tool_used: Skill` graders are scored, `--allow-tools` for the
slash cases, and `--runs 1` over the case files' `runs: 3`.

## Smoke check

`--case voice--slash` alone scored 1.00 ($0.10) and the full run's `voice--slash` scored 1.00 again, both against
the checkout under the home directory (the harness ran with the plugin path set to the repo root).

## What changed since the Phase 3 run

- New agent `delivery-checker`. Agents aren't skill-triggered, so it has no trigger case here. Its
  routing is covered by the reader-value tests, not this set.
- Description changes: `cold-reader` (135 to 101 characters), `tells-judge` (158 to 150) and `humanize`
  (165 to 156, "as check's fix step"). `cold-reader` and `tells-judge` are agents, so only `humanize` is in the
  trigger set; `humanize--de-ai`, `humanize--less-chatgpt` and `humanize--more-formal` all held.
- The deny-rule opt-out for auto-trigger (README host setup) changed no description.
- Two kaizen cases (`kaizen--natural`, `kaizen--slash`) now exist, taking the set from 28 to 30.
